
### 5.58 M53封存后分析已实现并冻结；尚未运行真实GT容量分析（2026-09-06）

本节接续5.57，不重复既有模型指标。新增 `tools/analyze_sttrack_m53.py`，不修改正在执行的采集器、实验spec、控制脚本、STTrack权重或容量门槛。独立的 `analysis_binding.json` 在本次实验GT分析前绑定新代码、执行绑定、原生训练绑定和合成检查器。

**分析顺序与口径。**必须先收到采集与控制进程两个零退出码，再核验63个序列产物的哈希、大小、事件帧覆盖、原生预测一致性、历史模板时序及同状态重放记录；全部通过后才打开GT。GT按原有零起点帧索引读取，无效GT事件单列，不用IoU=0混入均值。

| 分析模式 | 可以读取的历史模板 | 证据范围 |
| --- | --- | --- |
| default | 当前动态模板 | 原生单帧参照 |
| all_past | 全部严格早于当前帧的原生写入 | GT事后选择最佳视图的容量 |
| valid_past | 额外要求历史写入时GT IoU≥0.5 | 同时含GT写入筛选与最佳视图选择的特权诊断 |

三种模式均保留当前模板。因此最佳视图均值不下降是构造性质，不能作为读取策略安全的证据。程序另外统计：原本正确的事件被某次旧模板读取破坏的次数、相应读取分母、受害事件数，以及写入时框正确的历史模板子集中的同类损害。分别记录top1与top10最佳视图的来源帧，避免把两个不同视图的收益拼成一个真实选择。输出还区分“当前top10已有正确框，旧模板改善排名”和“当前top10没有正确框，旧模板产生候选”，并按当前重叠层次和序列拆表。

**实现验证。**手算矩形构造的检查已在服务器STTrack Python 3.8环境通过，覆盖最佳视图不一致、历史写入筛选、保留当前参照、健康读取损害、无效GT分母、排名与新增候选区分、JSON数值序列化；没有读取实验GT。独立GPT同家族Type-A咨询复核未发现具体代码缺陷，其本地裸Python检查曾在解释器shim处失败；该尝试保留在完整复核记录中，与服务器成功检查分别陈述。代码复核不能替代完整结果复算。

**下一步。**采集结束并封存后运行分析，按原先冻结的“至少10个严重错误事件、至少3个序列”读取容量条件判断。该条件仍仅使用all_past主分析；valid_past不取代主条件。通过只支持设计模板读取实验，不能跳过DepthTrack Train训练与递归验证，也不能宣称获得VOT/三数据集收益。当前仅完成分析实现和无实验GT的检查，尚无本节新增正式模型指标。
