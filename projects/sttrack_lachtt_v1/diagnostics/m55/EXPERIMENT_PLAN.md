# M55：TSG 张量复制修正的配对微调

本轮只检验两处 TSG 张量复制修正，在经过 DepthTrack Train 微调后，是否能改善完整递归跟踪。M54 的冻结模板读取器没有通过成功轨迹保护门，已停止晋升；本轮不继续调整它的阈值。

M55 的起点是已封存的源码、CPU 语义探针和真实网络前向证据：原 TSG 正向与反向分支共享被原地翻转的张量。修正前两分支的实际输入相同；使用独立副本后，分支输入能够区分。该证据证明实现行为发生变化，尚未证明任何跟踪指标提高。

## 唯一的模型干预

Control 使用原实现；Clone 仅修改 `lib/models/sttrack/sttrack.py` 的两处赋值：

```python
temp_x_flip = temp_x.clone()
temp_r_flip = temp_r.clone()
```

两组各有独立的 `lib` 和 `experiments` 副本，各封存 157 个文件的散列；两份代码只在上述文件的两处赋值上不同。正在进行原生 full127 评测的运行目录没有修改。

仍使用原有 ViT/BSI、两层 TSG、Mamba Fusion 和 Center Head。语言、候选关联头及 M54 读取器均不启用。完整递归验证保留初始化模板和默认动态模板，更新周期 50、阈值严格大于 0.75，固定旧 query 数量为 4。

## 固定数据与预算

| 项目 | 两组共同设置 |
|---|---|
| 初始权重 | `STTrack_Vot22.pth.tar`，严格载入并逐张量核对 |
| 基础权重 SHA-256 | `cacbd799115be1aaeb049cee0db89270851e3b6dd68997553b4c2c31c1104f98` |
| 数据划分 | 既有 M44 manifest 的 63 条 fit；22 条 development 仅用于训练后验证 |
| 模板／搜索 | 2 个 128×128 模板，4 个 256×256 搜索图；裁剪因子 2／4 |
| 采样与增强 | 原有 causal-with-replacement 采样及 ViPTProcessing |
| 微批次／累积 | 2 个片段，累积 4 次，等效优化批次 8 |
| 固定预算 | 15 轮 × 2,048 片段 = 30,720 片段／组 |
| 优化更新／搜索图 | 3,840 次／122,880 张／组 |
| 优化器 | AdamW，主干 LR 1e-5，其余 LR 1e-4，权重衰减 1e-4 |
| 损失 | 每帧 2×GIoU＋5×L1＋Focal，四帧求和，累积时取平均 |
| 梯度／LR | 梯度范数裁剪 0.1；第 10 轮结束后 LR 乘 0.1 |
| token 保留 | 第 1～9 轮 `[1]`；第 10～15 轮由原函数生成 `[1, .85, .7]` |
| 权重选择 | 固定第 15 轮最终权重，不按开发集挑选轮次 |

这是从已有权重出发的有界微调，采样量小于原配置的 15×15,000 片段；不称为复现原论文完整训练或从头训练。微批次为 2 时，BatchNorm 也按 2 计算，梯度累积不能复现物理 batch=8 的 BatchNorm；两组保持一致。

训练片段按明确的片段编号设置数据随机种子。逐批保存实际序列、模板／搜索帧编号和增强后输入张量的 SHA-256，训练结束后必须比较两组完整数据流，而不只比较配置文字。模型随机种子相同；自定义 CUDA 算子不承诺多次运行逐位相同。

原采样器并不保证四个搜索帧按时间排序，也允许重复抽取。M55 保留该行为，避免把排序变成第二个干预。因此本轮不是预测裁剪训练，也没有解决模板写入时机的训练—部署差异。

## 两项不同的训练检查

| 检查 | 实际执行 | 目的 |
|---|---|---|
| `contract_v2` | 两个固定 fit 片段，同一批次做 3 次优化更新，`keep_rate=[1]` | 核对真实网络的初始化、反向传播、参数更新和显存 |
| `sampler_contract` | 正式采样与增强产生 16 个片段，8 个微批次、2 次优化更新；分别测试第 1 和第 10 轮保留设置 | 核对正式训练器、随机输入、梯度累积和两种保留比例 |

`training_spec.json` 中的 `contract` 指第二项；两项输出目录、执行脚本及步数不同。最早的 `contract` 因探针把 `keep_rate` 错传为标量，在优化前退出；失败日志保留，不能据此判断模型性能。以上检查均未保留可采用的训练权重，没有递归或公开基准结果。

## 训练后验证与停止条件

先完成两组全部预算，并核对初始化、完整输入流、样本数、步数和最终权重散列。随后在固定 22 条 DepthTrack Train development 序列上运行完整因果轨迹，比较 Clone、Control 和独立原生 STTrack 基线。

冻结的主要晋升条件为：

- Clone 的有效帧 pooled mean IoU 至少比原生高 0.005，比 Control 高 0.002。
- `IoU <= 0.1` 的有效帧数及 H10 失败段数均不超过另外两条路径。
- 原生 H10 为 0 的任何序列均不得新增 H10 失败段。
- 完整报告全部 22 条结果，全部条件同时满足才通过。

沿用已绑定的统计函数：初始化帧和无效 GT 不计入平均值；无效 GT 帧会中断连续失败段。运行跟踪只使用初始化框及当前／历史图像，预测封存后才由独立统计脚本读取后续 GT。

开发集已被多次使用，不是新的未见测试。通过后先冻结低22评测；低22有明显改善且保护成功轨迹，再用同一个权重与运行策略验证 DepthTrack Test、CDTB 和 VOT full127。低22不能替代完整指标，三组数据不能拼接不同模型的成绩。

任何读取错误、执行错误或非有限损失／梯度都使训练以非零状态退出，不静默跳过、不自动重启。临时优化器状态写入 `/dev/shm`，重启会丢失；脚本没有自动恢复入口。服务器磁盘当时只有约 2.35 GB 空间，因此只将两组最终模型及日志留在磁盘，并在完成后做本地归档；不删除历史成果。
