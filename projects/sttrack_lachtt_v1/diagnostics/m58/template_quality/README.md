# M58默认模板条件的写入质量补查

M58文本版实际分数更低、默认模板写入更少，但这不能直接解释成模板更新不足。对已完成的同一开发22轨迹按默认条件重建，严重低重叠写入由原生27次减少到文本5次；有效GT写入中当前框IoU≥0.5的比例提高。同时，文本也跳过了更多当前框正确的定时更新。

| M58完成态开发22路径 | 重建写入数 | 写入时GT无效 | 写入框IoU≥0.5 | 写入框IoU≤0.1 | 有效GT写入中IoU≥0.5占比 | 跳过更新但当前框IoU≥0.5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原生STTrack | 292 | 9 | 256 | 27 | 90.46% | 168 |
| M58同预算纯视觉 | 237 | 2 | 214 | 21 | 91.06% | 239 |
| M58文本 | 178 | 3 | 170 | 5 | 97.14% | 287 |

三路各有654个每50步检查时刻，其中82个GT无效；文本在457个检查时刻当前框IoU≥0.5，纯视觉453，原生424。写入数量不同并不是文本可正确定位的检查时刻更少。三组已接受的写入中，0.1<IoU<0.5的中间区间计数均0。

同一物理检查帧对齐后，有146次原生写入、文本跳过，其中108次两者当前框均IoU≥0.5；另有7次文本框正确而原生框低重叠。相对同预算纯视觉，写入而文本跳过83次，其中55次两者框都正确，15次文本框正确而纯视觉低重叠。这些是不同递归路径的对应时刻比较，不能等价为只改变一次模板写入的因果实验。

## 对当前优化的意义

1. 当前证据同时支持“减少低质量写入”和“减少正确定位时的外观适应机会”。只按总次数判断更新太少或太多都不充分。
2. 当前框IoU≥0.5只表示该裁剪在几何上覆盖目标，不保证新模板更清晰、包含更多辨识属性，或未来比旧模板有用。不能把表中287个跳过时刻直接称为287次应该补回的更新。
3. 分数是原Hann响应最大值，不是经过概率校准的身份正确概率。这里报告的是实际阈值的经验选择结果，不据此拟合新阈值，也不将写入框达标比例称为语义理解准确率。
4. M59继续固定权重和默认模板规则，只干预文字内容。待其完整结果封存，再看文字是否影响响应、选框和模板频率；若后续需要研究更新可靠性，应在Train上另做配对训练/递归，不在当前运行中改策略。

## 方法与范围

读取冻结hash绑定的原生两个trace分片、M58两组44个完整预测文件及receipt，确认三家族封存。按继承STTrack代码的`frame_id % 50 == 0`且Hann最大响应严格大于0.75重建是否写入，再配对已有DepthTrack Train开发22的GT。初始化帧不参与，GT无效单列，不将其记为错误写入。

GT与M59使用的是同一训练开发集合已有GT；本次只将它与已完成M58的预测配对，没有读取正在运行的M59部分预测，也没有计算M59中途指标。结果字段M59_predictions_or_GT_analyzed=false指未进行M59结果分析，不意味着未打开任何GT文件。

没有新增模型调用、优化或阈值拟合，没有改M58/M59源、权重、文本或调度。代码执行退出0，计数与此前不读GT的292/237/178次重建一致。单种子、反复使用的开发22，当前模板未来效用仍未测量，不是VOT失败数/正式指标或因果结论。执行者分析不代表新的独立Astra/max审阅PASS。
