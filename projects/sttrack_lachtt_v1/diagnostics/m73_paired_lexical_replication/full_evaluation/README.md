### 完整运行链及同权重约束

新增M73全量辅助工具由已封存M64代码导出，变化主要为候选绑定、文本协议来源和低22输入复用路径；附带源码差异。全量入口先检查M73训练/内容/接口/low22的实际完成证据，再创建full_evaluation目录。任何一个前置条件未满足，入口停止，不生成新caption或推理结果。

获准后，DepthTrack Test和CDTB分别使用原首帧初始化、同一Qwen2.5-VL-3B生成协议、同一CLIP编码及类别保留操作；随后调用原OPE运行层写出框和原始置信度，并用绑定的PR/F评测源码计算完整指标。没有新增在线文本或类别提示，不手工修正自动描述。

完整VOT先导出既定1765个初始化及帧序，保留已冻结303条low22 caption/词向量/mask/初始化信息，只对剩余唯一观测生成新文本。若同一M73 bundle的low22已通过，完整运行可逐字节复用其909个轨迹/置信度/时间文件，接着计算其余1462 anchors；不会把原生STTrack或M64预测混入。最终仍由toolkit对完整127序列统一计算EAO/ACC/ROB。由于复用与新增轨迹的执行时段不同，不据此报告统一硬件速度。

新增最终检查器要求DepthTrack/CDTB每条序列文件和帧数齐全，绑定同一bundle与文本协议，逐文件校验框/置信度哈希，并从保存输出重新计算PR/F。VOT要求1765个anchor、5295个输出文件完整，检查toolkit分析及重新提取的失败记录。DepthTrack/CDTB使用原项目目标，VOT三项严格要求大于77.9/82.1/93.7。即使数值均通过，检查器也只写证据结果，线程目标还需核验全部任务要求、同步文档后再判定完成。
