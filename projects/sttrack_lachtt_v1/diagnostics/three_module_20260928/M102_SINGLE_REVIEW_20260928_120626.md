## Source conclusions

1. **Candidate binding and image semantics are correct.** The inherited constants point to the original M92 packet and legal M86 initialization register. Each manifest row must be fit, satisfy the stated IoU constraints, and bind its A/B indices to native/positive indices. Worker lines 101–108 use that index to mark the corresponding cached candidate box in the raw current image and load the same side's original M92 crop. The preparer saves each A/B crop from the same selected box with 15% context. It saves letters only into a separate annotated current image, which M102 does not load. The initial crop and red-marked initial full image use the same legal initialization box. All opened images are converted to RGB.

2. **The model prompt has the intended separation.** `inputs_for` constructs exactly four PIL-image entries and one constant text entry. Sequence names, source filenames, A/B letters, automatic category, candidate scores, GT boxes, and target side do not enter that text or chat image metadata. The original and swapped calls are `(initial_full, initial_crop, current_full, current_crop)` and `(current_full, current_crop, initial_full, initial_crop)`. The question treats both pairs symmetrically. Even positions retain the full-image budget of 512×28×28, odd positions the crop budget of 256×28×28; all minima are 128×28×28. This tests a new four-image/marked-current/Yes-No-Unknown protocol, not a single-factor explanation of M94's failure.

3. **Exact swapping is a real runtime prerequisite.** `image_blocks` partitions pixels by each grid's THW product and asserts four blocks and complete consumption. On each sanity event, both candidates must match grids and pixel tensors exactly under `(i+2)%4` before any binding flag is set. This comparison runs before device transfer. Both sanity candidates receive both orders, then the identical-initial self-pair is scored. Finite selected logits are asserted for every score call, including the self-pair. The self-pair answer is recorded without a favorable-answer gate, as planned. Source and mocks validate this logic; actual Qwen preprocessing/tensor equality is still pending.

4. **Scoring and aggregation match the declaration.** The worker derives three distinct single-token IDs from the installed tokenizer, runs the existing bfloat16 model in evaluation/inference mode, and reads the last-position logits. Each candidate's score is `Yes - No`; A/B ranking compares those margins within each order. Exact equality produces `tie`, never an A default. Both-order correctness requires both ranks to equal the train-GT localization side. A tie is incorrect; tie/tie is consistent, and tie/non-tie is a change. Per-order rank counters expose ties; per-order token counters include both candidates. The three-token softmax is restricted and uncalibrated. Neither an Unknown choice nor a positive ranking establishes physical identity.

5. **Coverage and launcher ordering are correct.** The manifest is required to have 24 rows. Slices `[0::2]` and `[1::2]` are disjoint 12-event sets; sanity uses the first event in each. Each child sees its assigned physical GPU through `CUDA_VISIBLE_DEVICES=0` or `1`, while its model targets visible `cuda:0`. The launcher starts both children, waits for both, then rejects any nonzero exit. It validates each one-event sanity status, shard and exact binding before starting full. Full outputs must each report 12 events and their expected shard; merging requires 24 unique audit IDs. A fresh output directory and worker nonexistence assertion preserve prior runs. There is no retry, model download, optimization, checkpoint save, tracker mutation, or promotion path.

6. **Published rows and gates stay within scope after the fix.** Full rows contain only audit ID, predictions/logits/probabilities, and ranks. GT-side/correctness is used only for multi-event aggregate counts. No v2 assignment is read. The plan correctly acknowledges that the original M92 seeded assignment is publicly reconstructible and must not be confused with an independently blinded human packet. The merged screening conditions are exactly both-order correct >=20/24 and rank changes <=2. Failed screens are retained. A passing screen still requires independent human review and cannot authorize semantic training or teacher use. The local M94 report supports the all-96-A failure premise; M101's local report supports its four visual-capacity checks, not independent semantic truth.
