At zero delta, `raw` already equals the saved float32 native boxes, but forming a rounded float32 corner and subtracting the position does not recover the original stored extent. ## Smallest correction

Keep `raw_right = raw_x + raw_w` and the existing side clamps, then compute

```python
corrected_width = (raw_w + (right-raw_right) - (left-raw_x)).clamp_min(10)
```

Use the analogous height expression. In real arithmetic this is exactly `right-left`; it only applies boundary clipping displacements to the stored extent. At zero corrections the current-data displacements are zero and the original extent is retained. No delta-equals-zero branch, detached output, tolerance relaxation, fallback, or extra exception path is needed.

This corrected arithmetic produced exact equality for all 30390 historical native boxes in binary32 emulation.
