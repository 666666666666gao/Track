# Train152：模板更新时点的GT标签覆盖

本项只读全部152条训练序列的缓存GT和已核对训练清单。使用零基50帧cadence点，尚未筛选原生0.75置信度资格，也没有运行跟踪器、W/K分支或C优化。因此下表是潜在时点的标签可用数，不是实际模板写入事件数、效用标签数或跟踪成绩。

| 未来窗口/帧 | 50帧时点数 | 当前GT未知 | 未来有有效GT | 当前/未来均可标注的共同集合 | 当前未知但未来可标注 |
|---|---:|---:|---:|---:|---:|
| 32 | 4324 | 322 | 4221 | 3984 | 237 |
| 64 | 4324 | 322 | 4272 | 3987 | 285 |
| 128 | 4324 | 322 | 4289 | 3988 | 301 |

1. 32帧窗口下，4221个时点的未来GT至少有一帧有效，其中237个当前GT未知，会被原计划的共同监督资格排除。这相当于未来可标注时点的5.6148%，以及当前GT未知时点的73.6025%。实际原生资格事件中是否也存在这批样本，需要R1/R2回放确认。
2. 16426个GT未知帧形成967段；152段长度超过32帧，占8756个未知帧，即53.3057%。未知不表示目标一定不在图中，也不表示当前预测属于其他实例。
3. 把窗口改为64/128帧，共同可标注数只比32帧增加3/4；新增可用时点主要仍属于当前未知组。这衡量标签覆盖，未测量更长窗口下动作价值是否更可靠或跟踪是否更好。

下一步保留现有32帧公平主对照，在R1/R2实际资格事件里分别报告共同样本、当前未知/未来可标注样本及其W/K效用分布。若后者数量和标签可用性足够，可以另立未来监督覆盖对照，明确额外监督数量和优化预算，保持当前GT未知而非填零。64/128帧跨过下一次50帧写入点；另建长窗教师时必须明确后续动作控制和新的因果范围，不能只改一个窗口常数。

现有C计划、R1源码和运行中R0的32份本地NN源文件保持原摘要。此检查读取219954个合法图像位置对应GT，其中152个初始化、219802个跟踪位置；沿用已核对toy07尾部39行无图像GT的既有截断。GT有效性复用旧审核函数；12972个prefix计数已逐个对照直接GT切片，导出的CSV又独立重聚合核对。结论范围限于C的标签覆盖；实际效用和当前VOT退化机制仍由分支回放与完整结果审核验证。

原始材料：result.json记录154份输入摘要及源码摘要；cadence_rows.csv保留12972条窗口记录，invalid_runs.csv保留967段，per_sequence.csv保留152条序列记录。CPU执行exit0，NN运行、服务器进度查询和优化均为0。
