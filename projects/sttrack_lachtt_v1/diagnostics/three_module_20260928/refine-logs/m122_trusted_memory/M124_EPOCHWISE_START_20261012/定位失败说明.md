# CDTB定位失败：准确类别为什么仍会跟丢

已完成模型：CurrentC。对正式已保存的预测框、分数、官方GT及失败附近30张RGB帧做CPU只读复核；未执行神经网络、未查询训练进度、未修改训练。帧号均为零基。红框是当前预测，蓝框是官方GT，黄框是按上一预测重建的factor4搜索crop。

准确类别与准确位置是不同的预测职责。此次证据不支持“全部是文字错了”或“全部是同类干扰物”。

## 背包：当前搜索根本没有包含重新可定位目标

[查看逐帧图](boxes_backpack_room_occ_1.jpg)

184–195帧GT无效，模型仍在天花板区域输出小框。196帧GT重新有效，GT框=[354.0,251.46,30.6,71.46]，上一预测产生的crop=[445,-93,257,257]，目标中心不在其中。即使backpack类别准确，当前输入缺少目标，也不能单靠文字给出正确位置。无效GT不单独证明物理遮挡/出画；实际多帧图显示目标与持物人物关系及重新出现位置。

## 垃圾桶：这条确实存在同类对象，类别不能确定是哪一只

[查看逐帧图](trashcans_room_occ_1_A.jpg)

画面里有前侧和后侧两只绿色垃圾桶。指定目标是后侧桶。468帧IoU0.880117，470帧0.497212，471帧0.210620，472帧为0；预测转到前側桶，后侧目标仍在crop内。两者都符合trashcan类别，因而准确类别不能独立提供实例区分。是否可靠属性和首帧身份分支被充分利用，仍需固定同状态的内容及候选干预，不能仅由这张图断言语言分支不起作用。

## 对整体召回的意义

当前CDTB P/R/F=74.593625/69.886239/72.163245%。原生STTrack R=68.067744%，当前R高1.818495个百分点；与目标75.6%相比尚差5.713761个百分点。固定全部保存框、取消报告分数过滤，R仅到70.554278%，分数筛选只损失0.668040个百分点。因此，主要差距来自轨迹定位质量与持续失锁，调报告阈值不足以达标。

全80条中10509个有效GT严重低重叠帧，8151个目标中心位于重建crop外。77.5621%是错误持续阶段的统计，不能写成77.5621%的首次错误都由crop外导致。另有目标始终在crop内的长错误段。

下一步应分别查：目标仍在输入里时的正确候选存在率、评分与框精修；目标不在输入里时的未可靠定位状态与新区域观察。继续使用已人工核验文字，不将准确类别当成无需验证视觉定位的保证。不对公开失败序列写专属训练或推理规则。

原始正式保存轨迹与图像哈希及数值保存在onset_rows.json；本报告是行为诊断，不是新部署成绩或完整因果消融。

## 从实际源码确认的限制

DenseTargetDecoder.forward中，语义增量full-null与视觉增量共同调整原生响应，再与quality概率组合，由response.argmax选一个位置；文本不是类别硬拒绝器，准确描述不保证最终排名正确。几何分支直接读取视觉特征，不直接输入文本，故正确类别也不能保证size/offset回归准确。

TrustedTemplateTracker.step先提交selected_box作为native.state，再记录observation_intersection_probability；该量没有用于拒绝位置提交或启动新区域搜索。C仅在原生interval50/threshold0.75允许更新时进一步控制动态模板。FullDenseTracker.observe始终按上一预测、factor4、256搜索输入进行局部观察。这是当前代码的真实职责缺口，不能据此宣布每个首次错误都由它引起。

当前完整联合训练继续相同网络职责，最多20轮能检验优化是否改善，不自动新增缺失的重新观察机制；不在运行途中加入新网络或改搜索规则。后续方案应在现有完整实验封存后根据候选诊断决定。
