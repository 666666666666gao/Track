# M124监督职责：目标在窗口里不等于已经定位正确

本次仅阅读本地源码；8份原始字节与已执行M124迁移请求的源文件SHA匹配。没有重新查询远端文件、训练进度、GPU或神经网络。此处描述当前M124，不能替代旧M67/M82路径的监督说明。

`m121_dense_inputs.py` L97–108的定义可写为p_obs的训练标签：

target = 1[area(GT ∩ crop ∩ image) > 0]。

这不是GT中心在crop内的标签。只露出一个有正面积的目标部分，即使GT中心在crop外，也可能记1；它也不评价是否有足够细节或合格候选。`train_m121_dense_target.py` L40–51先取得这个present，再用visible intersection中心所在cell建立热图和回归位置；回归仍与原GT框比较。原生正确峰另可进入可靠回归位置。这里只陈述实现，不认定边缘标签本身有错或是推车跳框根因。

因此，当前CPU轨迹中“GT中心在重建crop外”的统计，不能直接换成“所有这些训练状态都被监督为空目标/无回归”。M124与旧M67/M82的监督路径不同，必须分别报告。

对“准确类别、没有第二辆推车，为什么跳框”的意义：目标在窗口里时，observation=1完全可能与错误argmax同时成立；仅把observation低分接成拒绝门，并不能覆盖这类错误。候选quality有IoU监督，但实际是否在失败时正确排序仍需固定同状态的候选回放。C的当前质量监督与决策发生在模板资格处，不能修复非更新帧的选框跳转。

当前A+B+C联合训练确实会更新三个模块，GT只在动作之后计算损失，底座冻结；它没有因为训练轮数增加而改变这些标签或新增位置拒绝/新区域观察职责。C输入与selected_box标签detach，32帧累积不构成跨时间反传。新方案应在完整M124结果和最终选中权重诊断之后确定，不能在运行中修改标签、损失或搜索策略。

后续诊断需分别记录：窗口交集、GT中心、合格候选存在率、实际选择IoU、quality与框质量的误差、以及拒绝/重新观察动作。首先查候选存在与分数分项；不能以observation高或低单独宣布失败原因，更不能将预测概率直接当身份真值。当前准确人工类别继续使用。
