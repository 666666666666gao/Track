[GroundingDINO官方仓库](https://github.com/IDEA-Research/GroundingDINO)的标准接口输入图像与文字。固定源码中，transformer.py:291–315利用图文对应分数选encoder候选，并提取对应视觉内容/几何；groundingdino.py:333–349同时返回文字token分数与规范化框。它在模型中显式学习区域与文字对应，不能等同于把一份全局文本向量加入定位特征。

[固定推理源码](https://github.com/IDEA-Research/GroundingDINO/blob/856dde20aee659246248e20734ef9ba5214f5e44/groundingdino/util/inference.py)的第70–75行筛选依据是每个框对输入token的最大分数；第113–115行再将规范化cxcywh转为图像像素xyxy。因此，默认最大分数不能自动表示完整属性都被支持，更不是首帧实例身份置信度。若后续做只读对照，应先单独使用已核验类别，或明确类别短语对应的token范围，保留原始分数与框坐标；不能把多个属性的最大响应直接当身份核验。该标准接口没有首帧实例和Depth输入，不能直接替代RGB-D持续跟踪，也未在本项目验证。

[CLIP Surgery原文](https://arxiv.org/html/2304.05653)报告CLIP相似度图可能出现背景偏好和无关激活。它支持检查文字表征与空间定位的区别；不证明当前M124也存在相同根因。项目已有M84空参照差分及其边界，不能把减空文本重新包装为新方法，也不能从一张热图判定跟踪因果。
