## Blocking findings and minimal corrections

### B1 — K future boxes are never validated before scalar IoU

**Evidence:** `verify_template_write_teacher_raw.py:180` validates every native-prefix box. Lines 257–262 check future W/K frame IDs, previous-box continuity, query-list presence and selected-feature shape; line 258 also binds W records to that validated prefix. Lines 263–267 then compute both IoUs, but only GT is passed to `valid()`. There is no corresponding validation of `k['record']['bbox']`. The recursive tensor checker at lines 107–116 does not inspect scalar elements in bbox lists.

This is an actual acceptance gap in a verifier of saved records. Its own scalar `overlap()` and `equal_number()` accept K bbox `[100,100,-1,2]` against valid GT `[0,0,10,10]` as a finite reported IoU of **0.0**, even though the actual `valid()` function returns false. The reviewer reproduced this using only AST-selected standalone scalar definitions and `math`; no audited module import, NumPy, Torch, main, model or rollout executed. An invalid K box can therefore be counted as an ordinary zero overlap and affect the signed utility. On a last future row, the existing previous-box continuity check cannot reject it; on earlier rows, it only carries the value forward.

This invariant is grounded in the real writer: `dense_target_decoder.py:9–15` produces positive box dimensions and `full_dense_tracker.py:94–101` requires finite outputs before serializing its bbox. Validating the K box is necessary to make the independent readback enforce that actual writer contract, rather than trusting it implicitly. No corrupted R2 sample has been observed.

**Required minimal change:** before using either future prediction for labels, add `assert valid(k['record']['bbox'])` in the loop beginning at verifier line 256. W is already validated through exact prefix equality. Do not change the teacher, GT, labels or sign handling.

### B2 — K future records can assert a second template write and still pass

**Evidence:** the same verifier loop at lines 256–275 never checks the K record's `template_write` field. W is indirectly constrained by prefix equality and the prefix's 50-frame rule, but K has no matching assertion. A K record with otherwise accepted fields and `template_write=True` at event frame 50 + future frame 1 does not affect any of the verifier's K conditions or computed labels.

The actual writer explicitly forbids this: `template_write_forks.py:104–125`, particularly line 119, asserts no template write for every future frame of each branch. The event frame is divisible by 50, and the bounded future window ends at most 32 frames later, so this is the experiment's existing single-intervention requirement. This is not a new hypothetical policy.

**Required minimal change:** add `assert not w['record']['template_write'] and not k['record']['template_write']` to that future-frame loop. This checks the recorded action constraint for both branches. Preserve the existing bounds, own-history continuity and signed labels.

These two assertions are the necessary source corrections identified in this review. No fallback, exception handler, new data format, teacher restart or unrelated refactor is requested. Retain this failing v1, its exact input snapshot and counterexample when reviewing a revised verifier.

### B — Denominator and sign taxonomy

1. **Metrics/labels:** `overlap()` uses intersection divided by `w*h + gt_w*gt_h - intersection`, not max/min/mean of predicted confidence. Verifier lines 269–275 average **W minus K**, without clipping or taking absolute values. `equal_number()` allows only an absolute `1e-12` numeric discrepancy and requires null to remain null. The actual teacher has the same intended signed label definition at `run_template_write_teacher.py:140–156`.
2. **Unknown GT:** finite GT coordinates with positive width/height define validity. Invalid current GT yields `None`, not a negative IoU target. Future invalid frames retain null W/K IoUs. An empty valid-future set yields `delta_future=None`. Current validity plus at least one valid future frame defines common eligibility. Both branches always use the same GT-valid set.
3. **Retention:** collection/replay events are joined one-to-one before any label computation; all actual native-rule opportunities must match prefix events. Negative, zero, unknown and tail events remain in the teacher. Lines 279–293 retain signed label kinds and eligibility in the output. The signs in `STATIC_CHECKS.json` are scalar verification fixtures, not observed experiment outcomes.
4. **Model transforms:** `dense_target_decoder.py:18–22` is a pointwise odds transform, and lines 111–115 include the inference ratio `probability/native`; these are explicitly model-score transforms, not evaluation denominators. Feature L2/LayerNorm and the motion feature's prior predicted width/height denominators are input transforms (`template_write_features.py:15–24,29–39`). A prediction appearing in geometric union or an input transform is not by itself fraudulent metric normalization.
5. **Other supplied consumers:** C MSE uses sample count, and development frame/macro IoU use valid-frame count and equal sequence means (`train_template_write_C.py:139–150`; `analyze_template_write_C_dev.py:28–57,150–158`). The historical precision-loss denominator in `train_m122_full_causal.py:25–31` is a training-objective reduction; that objective is not called by the R2 teacher or the readback. H10 is a geometric low-overlap diagnostic, explicitly not VOT ROB.

B1 is distinct from score normalization: without K validity, an off-domain box can be silently treated as ordinary overlap even though the formula is mathematically correct on valid boxes.
