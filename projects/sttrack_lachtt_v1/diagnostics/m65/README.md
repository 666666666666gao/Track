## 为什么重新训练

M64把使用完整属性训练的M58权重切换到类别保留输入；这是一项实际存在的训练/部署协议差异，但尚未证明是M64失败的根因。M65的Control和Null都从M58同一零残差参数初始化开始，在训练与开发时均保留类别槽0，把有效属性槽1—4置为原CLIP空文本向量，保持5槽、mask和padding完全一致。没有新生成caption、重新编码embedding或手工修正自动类别。

Control沿用M58属性softmax；Null在该softmax中加入固定0 logit和0 value，支持不足时可减少语义context。两组可训练参数均为289,154，不添加学习的null向量、质量头、深度可靠性路由、在线文字或候选关联器。

在拟合集chair01_indoor验证：两组零残差模型的训练step和部署track在连续101次预测中，框、分数、query、模板状态与原生完全一致，包括第100帧模板写入。使用同一真实特征与非零M58权重，Control输出与原adapter逐元素相同，Null确实改变语义残差。这个局部样本上的无支持权重约0.0020—0.0271，只证明通道存在和计算正确，不证明已学会拒绝错误文字。
