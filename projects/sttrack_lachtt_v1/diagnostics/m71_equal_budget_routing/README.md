## 为什么需要这项补充

M70会从category和empty两次粗搜索各自的raw top10中映射到最多三个不同网格窗口。若多个峰映射到同一个窗口，实际数量可以小于三。因此直接比较原路由的候选容量时，词内容与观察窗口数可能一起变化。该可能性来自实际去重代码，不是凭空增加异常分支；目前尚未读取M70模型输出，不能说已经观察到数量差异或文字优势。

M71保留原M70全部结果，在它完成后增加严格同窗口数的读出，并加入只看上一预测位置的几何对照。模型仍是M65 Null固定最终head，类别保留协议，且每个探测共享其真实递归历史。M65原失败门结论不变；这不是新训练版本，也没有候选接管状态。

## 冻结的同窗口数分析

主分析逐事件使用`min(3, category实际路由数, empty实际路由数)`个细窗口，两种文字路由与历史几何对照使用完全相同数量。补充固定k=1、2、3；只有两种文字路由都能提供至少k个不同窗口的事件进入相应k集合，逐项报告未进入的事件，不补假窗口、不重复窗口。

几何对照将与M70完全相同的网格按上一公开bbox中心的平方距离排序，同距离按原网格编号排序。它不读取当前GT、类别或图像特征。该对照不需要粗搜索前向，实际比文字路由更便宜；M71严格匹配的是细窗口数，不声称所有方法总计算成本相同。

在上述同样的细窗口预算内，固定四个比较：

| 比较 | 保持相同的部分 | 回答的问题 |
| --- | --- | --- |
| category路由/category细定位 vs empty路由/category细定位 | 细定位文字与权重 | 内容是否改变了去哪里观察 |
| category路由/category细定位 vs category路由/empty细定位 | 观察窗口 | 内容是否改善了窗口内预测 |
| category/category vs empty/empty | 权重、历史状态、窗口预算 | 两阶段内容改变的联合效果 |
| category/category vs 历史位置路由/category细定位 | 细定位与细窗口数 | 粗搜索是否优于只依赖历史位置 |

主读出为raw NMS top10，另报Hann与全部256位置的容量。分别记录正确候选存在、最高分是否正确、严重错误、最佳/选中IoU；同时按事件、按序列等权统计配对差值。严重错误增加是坏事，所以输出字段使用中性的`increases/decreases`，不将任何原始数值增加笼统称为胜利。

所有216个事件都纳入主共同预算分析，并分别报告H10框内、框外、中心确在完整图内、GT恢复有效和健康子集。事件是GT选出的事后诊断位置，不能据此估计部署触发误报率。category对empty也还不足以证明正确词义优于错误词义，不能把该诊断直接写成同类实例语义理解。
