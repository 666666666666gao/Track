## 为什么单独做这个诊断

当前原生STTrack的VOT已经接近目标，而同一权重的DepthTrack/CDTB仍有缺口。VOT区域指标与长期P/R/F的计算不同：后者使用逐帧上报置信度对预测进行排序与选择。原始Hann最大值既参与定位后的模板判断，也被用作上报分数。M67训练的无支持槽提供另一个可观测量，但它是否具有目标存在性信息仍待验证。

M68只检验一个预先固定的读取方式：

`reported_confidence = raw_Hann_peak × (1 − null_mass_at_actual_Hann_argmax)`

同一M67 final分别输出原始分数及上述乘积分数；Control与Support两组都检查。初始化上报分数为1。无支持概率严格来自原有5槽mask加固定零logit的float32 softmax，取当前实际Hann最高峰的位置；乘积使用转为Python float的两个量，按原接口保留6位小数。

这一公式没有新增参数或阈值。它是待验证的支持分数，不是已经校准的目标存在概率，更不是caption正确性的证明。

## 保持定位和模板路径不变

代码在原adapter和Center Head的forward hook中只保留detach后的输出副本，没有第二次网络前向，也不回写bbox、query、模板或响应。模板更新仍执行原始分数大于0.75的50帧检查，乘积分数不参与任何跟踪状态决策。

实际回放必须逐帧等于M67已封存的公共框和原始分数，否则中止，不能继续报告该实验为固定轨迹对照。输出两种置信度的TXT框文件还须逐字节一致。完整hook回放一致性尚未实测，当前通过的是准备检查。
