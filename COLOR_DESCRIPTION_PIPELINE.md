# Frame-aligned color description pipeline

The project now uses the existing `color_desc` convention directly. New
annotations are not converted to JSONL.

## Layout

```text
color_desc/
  depthtrack_train/            # DepthTrack per-frame train annotations
    <sequence>/color_description_ct.txt
  depthtrack_test/
    <sequence>/color_description_ct.txt
  cdtb/
    <sequence>/color_description_ct.txt
  votrgbd2022/
    <sequence>/color_description_ct.txt
```

Each file is UTF-8 plain text. DepthTrack train keeps one line per RGB frame,
so line `N` describes frame `N`. DepthTrack test, CDTB, and VOT-RGBD2022 each
contain exactly one line describing frame 0. Blank, missing, and extra lines
are rejected instead of being silently padded or shifted.

The generator also keeps a `*.resume.json` sidecar containing operational
checkpoint metadata. It binds the committed text to the initial image, its GT,
the local model paths, and prompt versions, and lets an interrupted partial
tail be discarded safely. This sidecar is not an annotation and is not JSONL;
`color_description_ct.txt` remains the only formal annotation consumed by the
tracker.

## Local models

- Qwen2.5-VL-7B creates the visual draft from the RGB frame and ground-truth
  target region.
- Qwen3-8B is text-only. It corrects grammar, length and forbidden annotation
  terms without claiming to re-check the image.

## Evaluation protocol

DepthTrack train uses its existing per-frame text with
`TRAIN.LANGUAGE_TEXT_MODE: current`. Qwen2.5-VL receives the first-frame GT
region for each evaluation sequence. Evaluation therefore uses
`TEST.LANGUAGE_TEXT_MODE: initial` and holds that one initial description
fixed throughout the sequence.

The official DepthTrack test split is not used for validation. Validation is a
fixed 10% sequence holdout from the DepthTrack training split; the remaining
90% is used for training.

Horizontal flips are disabled in this language configuration. The training
descriptions contain directional words such as `left` and `right`, so flipping
the image without rewriting its text would break frame/text alignment.

Default model locations:

```text
D:\steam\RGB-D-L-work\models\Qwen_VL\qwen2.5-vl-7b
D:\steam\RGB-D-L-work\models\Qwen3_8B
```

## Commands

Use the CUDA-enabled `sam3` environment. A one-sequence pilot can be written to
an isolated output root:

```powershell
E:\anaconda\envs\sam3\python.exe tools\annotate_color_descriptions.py `
  --dataset depthtrack_test --stage all `
  --max-sequences 1 `
  --output-root color_desc\_pilot --load-in-4bit --overwrite
```

The full resumable command is:

```powershell
E:\anaconda\envs\sam3\python.exe tools\annotate_color_descriptions.py `
  --dataset depthtrack_test cdtb votrgbd2022 `
  --stage all --load-in-4bit
```

For each sequence the tool writes one initial-frame
`color_description_qwen25.txt`, then one corrected
`color_description_ct.txt`. There are 257 evaluation sequences in total
(50 + 80 + 127), so the full job is 257 visual drafts plus 257 text
corrections. Existing committed output resumes through the sidecar. A legacy
output with no sidecar is deliberately rejected; use `--overwrite` to restart
it. The supplied DepthTrack train text set remains the complete per-frame
annotation source and is not regenerated by this command.

The 4-bit path uses a fixed placement map. `--gpu-memory` and `--cpu-memory`
caps are rejected with `--load-in-4bit` because Accelerate cannot enforce
those caps for that map.

## Training

Use the frame-language configuration:

```powershell
$env:RGBDL_OSTRACK_PRETRAIN = "E:\1111\OSTrack_RGBD_L_dataset_modified\pretrained_models\OSTrack_ep0300.pth.tar"
$env:RGBDL_ROBERTA_MODEL = "E:\1111\OSTrack_RGBD_L_dataset_modified\pretrained_models\roberta-base"

python tracking\train.py --script mplt_track `
  --config vitb_256_mplt_32x1_1e4_depthtrack_15ep_color_desc `
  --save_dir .\output\depthtrack_color_desc --mode single --nproc_per_node 1
```

The baseline remains unchanged unless `MODEL.LANGUAGE.USE` is enabled. When it
is enabled, the current frame description is encoded by the configured frozen
text encoder and used to modulate the fused RGB-D search feature.

The two environment variables keep machine-specific model locations out of
the YAML. Replace their values when the pretrained assets move.
